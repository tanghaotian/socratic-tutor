# 0.4.0 学习计划阶段 + 复盘阶段（交叉确认 / 加权锚定反思 / 组合进化）

## Context

Socratic Tutor 目前能按回答信号更新画像（ProfileEngine）、每周自我升级（ReflectionEngine）、生成能力 skill 并评测（SkillGen/EvalGate），但**缺少对"学员学习过程"的阶段化跟踪**：没有学习计划文档（学什么、目标、怎么学），也没有学习周期结束后的复盘文档（学得怎么样、偏差在哪）。用户要求新增两个阶段：

1. **学习计划阶段**：按主题生成学习计划 md，跟踪确认学习情况。
2. **复盘阶段**：计划周期结束时生成复盘 md，复盘确认。
3. 两阶段**交叉确认**：复盘与计划比对 → 动态更新学员画像 → 影响后续计划。
4. **加权评分 + 锚定反思**：多次（连续 N 次）加权评分不理想 → 自我确认反思画像锚点是否有误 → 自动修正锚点 + 审计。
5. **自我进化**：plan/review 两阶段生成能力也要进化，用**组合加权评估**（计划质量 + 复盘质量联合打分）确认是否真的优化了这两阶段能力，达标才应用。

已与用户确认：按主题粒度、复盘为独立新引擎（与每周反思分开）、锚定修正自动执行+审计、进化用可插拔能力 + A/B 组合加权评测。版本定位 0.4.0。

## 数据模型（要点）

```ts
type DocStatus = 'draft' | 'confirmed';
interface AnchorSnapshot {
  initialMastery: Record<string, number>; // 初始掌握度假设
  targetDepth: number;                    // 1-5
  targetDifficulty: number;               // 0-1
  learningSpeedBaseline: number;          // ≥0.1
  repetitionBias: number;                 // 0-3
}
interface StudyPlan {
  id; learnerId; period:{start,end};
  goals: { topicId; targetLevel; targetDepth; sessions }[];
  strategy; anchors: AnchorSnapshot; status: DocStatus; createdAt; updatedAt; generatorVersion?;
}
interface ReviewScore {
  goalCompletion; signalAccuracy; frequencyRate; masteryChange; weighted; // 0-1
}
interface StudyReview {
  id; learnerId; planId; period:{start,end}; scores: ReviewScore;
  findings[]; improvementNotes[]; anchors: AnchorSnapshot; status; createdAt; updatedAt; generatorVersion?;
}
interface AnchorAdjustment {
  id; learnerId; reviewId; trigger:{streak; threshold};
  before: AnchorSnapshot; after: AnchorSnapshot; method:'llm'|'heuristic'; reasons[]; createdAt;
}
interface PlanReviewStrategyConfig { // active.json 条目
  id; kind:'plan'|'review'; version; planPrompt?; reviewPrompt?; weights?; heuristics?;
}
```

SQLite 新表（风格同 reflections）：
`study_plans(id,data,updated_at)`、`reviews(id,data,updated_at)`、`anchor_adjustments(id,data,updated_at)`。
新增 API：get/save/list StudyPlan、get/save/list Review、saveAnchorAdjustment、listAnchorAdjustments、`exportPlanMarkdown`→`data/plans/<id>.md`、`exportReviewMarkdown`→`data/reviews/<id>.md`。

## 加权评分（scoring.ts，纯确定性）

`weighted = 0.4*goalCompletion + 0.2*signalAccuracy + 0.2*frequencyRate + 0.2*masteryChange`（权重经 `plan.reviewWeights` 可配，读取时 clamp 并归一化）。分项：goalCompletion=目标 topic 达 targetLevel 比例；signalAccuracy=correct/(correct+mistake+confused)；frequencyRate=min(1,实际会话数/计划 sessions 和)；masteryChange=avg(Δlevel)/avg(targetLevel−初始)，下限 0。

## 锚定反思（anchor.ts）

- 触发：最近连续 `plan.anchorStreak`（默认 2）条 review 的 weighted < `plan.anchorThreshold`（默认 0.5）。
- LLM 修正：输入画像+当前锚点+最近两条复盘 JSON，structuredCall 输出新锚点+reasons，逐字段 clamp 后采用（method=llm）。
- 启发式降级：initialMastery←实际期初掌握度；learningSpeedBaseline←ΣΔlevel/会话数（下限 0.1）；targetDepth←round(目标深度×goalCompletion)；repetitionBias←max(0, 3−周期平均正确率×3)（method=heuristic）。
- 审计：`saveAnchorAdjustment` 落 SQLite + `data/anchors/<reviewId>.md`（before→after、method、reasons）。

## 交叉确认（crosscheck.ts，复盘 confirm 时触发）

达标 topic → 画像 masteryDelta + interest 增量（`applyProfileDelta` 复用）；未达标 → improvement 注记。随后检查锚定触发。

## 进化评估（eval.ts）

- `PlanReviewStrategy { id; kind:'plan'|'review'; version; generatePlan(ctx); generateReview(ctx); describe() }`，`StrategyContext { learnerId; profile; anchors; topicId?; previousPlan?; planId?; history[]; llm?; weights }`。
- 候选来源（MVP）：参数变体（权重/提示词组合成 PlanReviewStrategyConfig），不做 LLM 写 TS 源码。
- `runStrategyEval({baseline, candidate, threads(冻结线程 3-5 条), profileSamples, judgeProvider})`：两版策略各生成 plan+review → judge 按两维打分（planQuality: 目标合理/难度适配/可执行；reviewQuality: 分析深度/评分合理/建议可操作，各 0-10）→ `combined = 0.5*planScore + 0.5*reviewScore`。
- verdict（对齐 selfbuilt L83-L117）：combined≥6 且 candidate>baseline → **accepted**；≥6 无提升 → needs_review；<6 → rejected；judgeDegraded → needs_review（不自动应用，防无监督劣化）。
- 应用：accepted → `applyStrategy(cfg)` 写 `data/plans/active.json`（幂等覆盖）；`createStrategyManagerFromRegistry(dir)` 装配时叠加到默认策略，重启生效。

## 风险与简化

- 进化评估 MVP 仅手动触发 + 少量冻结线程；judge 缺失一律 needs_review，不自动应用。
- 候选版本用参数变体而非 LLM 生成 TS 源码（省代码生成/编译风险，留接口后续演进）。
- 锚点不加 LearnerProfile 字段（latest adjustment 即当前锚点）；profile.ts 仅加 export，行为不变。
- 评分公式纯确定性保证可复现；LLM 只产出定性内容。
